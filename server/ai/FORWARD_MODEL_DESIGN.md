# 경량 Forward Model + Search — 설계 문서 (v1)

작성 2026-06-14. 목적: greedy 봇(평균 ~58점)을 **다턴 미래를 내다보는 search 봇**으로 바꿔 사람 수준(180+)에 근접.

---

## 0. 왜 이게 필요한가 (근본 원인)
- 현 봇은 greedy 1-ply: 매 수 "즉시 eval 최댓값"만 고름 → 3라운드 뒤 빛볼 엔진 투자를 못 봄 → 작은 엔진(구조물 9 vs 사람 14, 연방 1.4 vs 4.5).
- search를 붙여봤으나(terminalRollout) **유의 음성(-12VP, p=0.002)**. 원인: 롤아웃 스텝마다 **무거운 진짜 엔진**(StateCloner deep-clone + 서버 performAction 전체검증) → 0.6초에 롤아웃 1~2회 → 탐색 굶음.
- **결론: 병목은 search 개념이 아니라 시뮬 비용.** 시뮬을 50~100배 빠르게 하면 같은 시간에 수백 롤아웃 → 진짜 다턴 계획 가능. (알파제로 방식 = 빠른 시뮬 + 대량 search.)

## 1. 목표 & 성공 기준
- **1차 성공(채택 게이트):** search 봇이 head2head에서 현 greedy 챔피언을 **유의하게 이김**(VP +, 승률 >55%, p<0.1, 40+판).
- **최종 목표:** 1:3 실전에서 승자봇 점수 분포가 현 ~58 → **100+** (사람 180과는 별개로, 큰 도약).
- **속도 게이트:** 경량 롤아웃이 현 대비 **≥50배 빠름**(0.6초에 ≥150 롤아웃).
- **정확도 게이트:** 경량 모델이 예측한 "트라젝토리 최종VP 순위"가 진짜 엔진 결과와 **Spearman ρ≥0.6** + 후보 수 ordering 보존.

## 2. 재활용 자산 (from-scratch 아님)
- `mcts.ts: simulateToTerminal` — 롤아웃 뼈대(이미 있음, 엔진만 교체).
- `gameState.ts: scoreTerminalStateForRollout` — 종료점수(최종미션+연구+잔여+비딩). 경량 상태용 버전 필요.
- `gameConfig.ts: getNextRoundIncomePreview` — **검증된 income 계산**(rolloutIncome.ts가 이미 래핑). 그대로 사용.
- `features.ts: extractFeatures` — 경량 상태 추출의 출발점.
- head2head/variant flag 하네스 — 검증 인프라.

## 3. 핵심 설계: SimState + 빠른 전이
### 3.1 SimState (compact, 복제 싸게)
플레이어당 평면 숫자 + 최소 맵 추상. 깊은 객체 트리 금지(복제비용 폭증 원인).
```
SimPlayer = { ore,credits,knowledge,qic, p1,p2,p3, score,
  mines,ts,labs,pi,academies,         // 구조물 수
  research[6], feds, techTiles, gaiaformers, bonusTileId,
  // 확장/연방 추상(아래 3.3):
  reachableSlots: {steps0,steps1,steps2}[],  // 닿는 빈 행성: 테라포밍비용별 개수
  clusters: number[],  // 미연방 클러스터별 현재 파워합(7 도달 추적용)
  passed: bool }
SimState = { round, players[4], meIndex, sharedPools(파워액션/보너스타일 가용) }
```
- 맵 전체 대신 **"닿는 슬롯 개수(비용별)"+"클러스터 파워합"**만 추적 → 위치 정보를 잃지 않으면서 100배 가벼움.

### 3.2 빠른 전이 (performAction 대체)
액션 타입별 O(1) 상태 변경:
- **build_mine**: reachableSlots에서 가장 싼 슬롯 1개 소비(ore/credit 차감), mines++, 해당 클러스터 파워합 += 1. 슬롯 없으면 불가.
- **upgrade(TS/lab/PI/academy)**: 비용 차감, 카운트 이동, 클러스터 파워합 += (값 증가분).
- **advance_research**: knowledge -=4, research[t]++, L5 보상 즉시 반영(이미 룰 있음).
- **form_federation**: 파워합 ≥7 클러스터 1개 소비 → feds++, 보상(VP/자원), 그 클러스터 제거.
- **pass**: 보너스타일 VP + passed=true.
- **income(라운드 경계)**: getNextRoundIncomePreview 기반(검증됨).
- 우주선/고급타일/종족특능: v1은 **coarse**(평균 보너스로 근사하거나 생략, eval로 보정).

### 3.3 연방 문제 (이 프로젝트의 핵심 난점)
연방은 위치(7파워 인접 클러스터) 의존 → positionless면 못 셈.
- **v1 해법:** 롤아웃 시작 시 **진짜 맵에서** 미연방 클러스터들의 현재 파워합 + "1확장 추가 시 7도달 여부"를 추출해 `clusters[]` 초기화. 롤아웃 중 build/upgrade는 가장 가까운 미달 클러스터의 파워합을 올림(어느 클러스터인지는 근사: 큰 것부터). 7도달 시 연방 후보.
- 부정확하지만 **"엔진 키우면 연방 열린다"는 인과 방향**은 잡음. 정확도 게이트(2)로 검증.

## 4. 무엇을 정확히 / 근사 / 생략 (속도-정확도 트레이드오프)
| 요소 | v1 처리 | 이유 |
|---|---|---|
| income | **정확**(getNextRoundIncomePreview) | 엔진 성장의 핵심, 이미 검증됨 |
| 건설/업글 비용·VP | **정확** | 룰 단순, 결정적 |
| 연구(비용/L5보상) | **정확** | 룰 있음 |
| 연방(7파워→보상) | **근사**(클러스터 파워합 추적) | 위치의존, 3.3 |
| 확장 가능량 | **근사**(시작시 맵에서 슬롯 추출) | 위치의존 |
| 라운드/최종 미션 | **정확**(scoreTerminalStateForRollout) | 점수 직결 |
| 우주선/고급타일/종족특능 | **coarse/생략** | 복잡, v1 후순위 |
| 상대 턴 | **같은 fast 정책으로 시뮬** | 경쟁 반영 |

## 5. 단계별 구현 (브릭 + 검증 게이트)
각 브릭은 독립 검증. 게이트 실패 시 **중단 또는 재설계**.
- **B0. SimState 정의 + 추출기** (ServerGameState→SimState). 게이트: 핵심지표(자원·구조물·연구·연방) 왕복 일치.
- **B1. 빠른 income** (rolloutIncome 재사용, SimState판). 게이트: 진짜 income과 자원델타 일치(이미 검증된 함수라 통과 예상).
- **B2. 빠른 전이**(build/upgrade/research/fed/pass). 게이트: 샘플 상태 100개에 액션 적용 → 진짜 엔진 결과와 자원/구조물 델타 오차 <5%.
- **B3. SimState 종료점수**(scoreTerminalStateForRollout 포팅). 게이트: 동일 최종상태에서 진짜 점수와 ±3VP.
- **B4. 순수 경량 다턴 롤아웃**(현재→R6, 4인 fast정책). **게이트A(속도):** ≥150 롤아웃/0.6초. **게이트B(정확도):** 경량 예측 최종VP가 진짜 엔진 풀게임 결과와 Spearman ρ≥0.6. ← **여기서 실패하면 프로젝트 중단**(근사가 부족 = 더 정교한 모델 필요, 비용 급증).
- **B5. MCTS 연결**(simulateToTerminal를 경량 롤아웃으로 교체, flag fastSearch). 게이트: head2head 40판 vs greedy 챔피언 → **유의 우위**(VP+, 승률>55%, p<0.1). ← **채택 게이트**.
- **B6. 튜닝**(롤아웃수/정책/연방근사 정밀화) → 승률 최대화. + 우주선/고급타일 모델 추가(2차).

## 6. 속도/정확도 목표 (구체 수치)
- 현재: 롤아웃 1스텝 ≈ deep-clone(~수ms) + performAction. 풀게임 롤아웃 ~수백ms → 0.6초에 1~2회.
- 목표: SimState 복제 <5μs, 1스텝 전이 <10μs, 풀게임(~40스텝) <0.5ms → 0.6초에 **>1000 롤아웃**(여유). MCTS 오버헤드 감안 ≥150 보장.

## 7. 위험 & 중단 기준 (네 시간 보호)
- **R1 정확도 부족**(B4 게이트B 실패): 연방/확장 근사가 너무 거칠어 예측이 실제와 무상관 → **중단**. (가장 큰 리스크. value-net이 노이즈로 죽은 것과 같은 실패모드.)
- **R2 속도 미달**(B4 게이트A): SimState가 여전히 무거움 → 표현 더 압축. 통과 쉬울 듯.
- **R3 B5 무효**: 빠르고 정확한데도 head2head 개선 없음 → eval/정책 문제. oppRollout 교훈상 가능성 있음.
- **단계별 게이트로 매몰비용 차단:** B0~B3는 1~2일(저위험). B4가 분수령(여기까지 와서 ρ<0.6이면 접음). B5가 진짜 보상.

## 8. 실행 순서 제안
1. B0~B1 (상태+income) — 빠르고 안전, 토대.
2. B2~B3 (전이+종료점수) — 정확도 검증 시작.
3. **B4 분수령** — 속도+정확도 게이트. 여기 통과해야 의미.
4. B5 채택 게이트(head2head).
한 번에 다 안 함 — B4까지 가서 게이트 보고 계속할지 결정.

---
**현실적 기대:** B4 통과 확률이 이 프로젝트의 성패. 통과하면 봇이 처음으로 진짜 다턴 계획을 하게 됨(큰 도약 가능). 못 가면 "Gaia는 경량 근사가 어렵다"를 확인하고 중단(매몰비용 최소). 사람 180+ 보장은 없지만, 58→100+는 현실적 사정권.

  Gaia는 search가 greedy를 이길 만큼 **빠르면서 동시에 정확한 경량 모델**을 만들기가 매우 어려움(설계 R1 리스크 현실화).
